Adding Hudder as a Gradle dependency

You will need the Fabric API for hudder to function First you will need to add modrinth's maven repository in the build.gradle file:

repositories { ... exclusiveContent { forRepository { maven { name = "Modrinth" url = "https://api.modrinth.com/maven" } } filter { includeGroup "maven.modrinth" } } }
After that you'll need to add Hudder's dependency: dependencies { modImplementation "maven.modrinth:hudder:[Hudder modrinth release version]" }
...And done! You are now ready to start expanding hudder!



Creating your own variables

In the Hudder compiler, all system variables must return always return a value. Prior to 10.3.0, the method for registering variables is DataVariableRegistry.registerVariable([Variable], VariableTypes.[TYPE], [Names]); In 9.0.0 the ObjectDataAPI has been deprecated and marked for removal in-favor of DataVariableRegistry, in 10.0.0 it was removed. Want to add your own variables? For that you can use the DataVariableRegistry.
Example: // Register a String variable DataVariableRegistry.registerStringVariable(k->"Walter white", "name"); // Register a Number variable DataVariableRegistry.registerNumberVariable(k->308, "address"); // Register a Boolean variable DataVariableRegistry.registerBooleanVariable(k->true, "dead", "2nd_variable_name"); // Register a Variable of any type DataVariableRegistry.registerObjectVariable(k->new Object() { @Override public String toString() { return "This is a dummy object"; } }, "dummy_object"); The registerations functions are defined as such: public static <T> void registerStringVariable(DataVariable<String> variable, String... names) public static <T> void registerNumberVariable(DataVariable<Number> variable, String... names) public static <T> void registerBooleanVariable(DataVariable<Boolean> variable, String... names) public static <T> void registerObjectVariable(DataVariable<Object> variable, String... names)

They are guranteed to be applied to all first party compilers included in Hudder as well as any third party compilers that uses the DataVariableRegistry getters.



Creating your own Functions and Consumers (Methods)

Hudder calls "consumers" "method" but they behave the same The `position` and `config` were added in 10.3.0, the older methods have also been deprecated. Want to add your own custom functions and consumers for existing compilers (Ex. Hudder or JavaScript)? For that you can use the FunctionAndConsumerAPI.

It allows you to add your own functions and consumers using the registerPositionedFunction(BindablePositionedFunction, names...) and registerPositionedConsumer(BindablePositionedConsumer, names...) respectively.


Both Consumers and Functions take the same arguments: AUIElementManager, ATextCompiler and ObjectWrapper[].

AUIElementManager is the compiler's UI Element manager, use it to add UI Elements (Either ones custom made or one built into hudder).
AUIElementManager has the following Functions:
Function Description
void addUIElement(AUIElement element) Adds the provided AUIElement to the UIElementManager.
AUIElement[] toUIElementArray() Returns all the elements in the UIElementManager in the form of an array.


AHudCompiler<T> is the compiler that has called this function to be executed (ex. If the function was called using Hudder, then HudderV2Compiler will be provided, if it's JavaScript than JavaScriptCompiler will be provided, etc.)

T is the type of object the compiler takes as input

Some of the methods AHudCompiler<T> provides include:

Method Description
T processFile(HudderConfig config, String filepath) throws CompileException, IOException Processes the file at the given path into something the compiler can execute.
HudInformation execute(HudderConfig info, T processedFile, String filename) throws ExecutionException Execute the processed file.
Object getVariable(String key) throws ExecutionException Returns a variable with the key, could be a system or user defined variable.
HudInformation processAndExecute(HudderConfig config, String filepath, String filename) throws CompileException, ExecutionException, IOException Processes the given file and executes it.
String[] getSupportedFileFormats() Returns an array of file formats this compiler supports
boolean isValidFilePath(String filepath) Returns whether or not this compiler supports this file
void edit(File file) Open the given file in a supported editor


ObjectWrapper[] is an array containing all the values passed into the functions.
ObjectWrapper has the following functions:
Function Description
Object get() Returns the value of the arguement.
String asString() Returns the value of the arguement in the form of a String.
double asDouble() Returns the value of the arguement in the form of a double.
Object[] asArray() Returns the value of the arguement in the form of an array of Objects.
boolean asBoolean() Returns the value of the arguement in the form of a boolean.
T asType(Class<T> clazz) Returns the value of the arguement in the form of T.
float asFloat() Returns the value of the arguement in the form of a float.
int asInt() Returns the value of the arguement in the form of a int.
long asLong() Returns the value of the arguement in the form of a long.
float[] asFloatArray() Returns the value of the arguement in the form of an array of floats.
Component asComponent() Returns the value of the arguement in the form of a Minecraft text Component.
Identifier asIdentifier() Returns the value of the arguement in the form of a Minecraft Identifier.




To create your own function do the following: FunctionAndConsumerAPI.getInstance().registerPositionedFunction((elementmanager,compiler,position,config,arg)-> { if (arg.length<1) throw new ExecutionException("sayhi function requires at least one arguement!", position); String name = arg[0].asString(); return "Hi " + name + "!"; }, "sayhi");


To create your own consumer do the following: FunctionAndConsumerAPI.getInstance().registerPositionedConsumer((elementmanager,compiler,position,config,arg)-> { if (arg.length<1) throw new ExecutionException("sayhi function requires at least one arguement!", position); String name = arg[0].asString(); Hudder.alert("Hi " + name + "!"); }, "sayhi");



Creating your own UIElements

You should see the fabric wiki page for using the Drawing Context for more information.

 To create your own UIElement you simply need to create a class that extends AUIElement and override the renderElement method.

The AUIElement class is the base class for all UIElements. It provides the basic functionality for rendering and managing UIElements. It has only one method: renderElement(GuiGraphicsExtractor graphics, HudderRenderer renderer, DeltaTracker delta).

Here is a quick description of the arguments in the renderElement method:
Argument Description
GuiGraphicsExtractor graphics Minecraft's graphics extractor object.
HudderRenderer renderer The HudderRenderer instance used to render this UIElement, it also contains methods that may assist you with rendering.
DeltaTracker delta The delta tracker used to track the changes in the UIElement.
