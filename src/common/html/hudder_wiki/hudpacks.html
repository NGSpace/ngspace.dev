Hudpacks


Hudpacks were added in Hudder version 10.0.0 Hudpacks use JavaScript for the code itself. See JavaScript Hudpacks allow you to organize Hudder huds into their own directories and control them through JavaScript. Instead of using a single hud file, a hudpack acts more like a small project containing scripts and metadata.

Setting up a Hudpack

Before we can start writing our hudpack, we first need to configure Hudder so it knows we want to use one.

Follow these steps:

  1. Open Hudder's settings and go to the Advanced section.
    Set the Compiler type setting to pack.
  2. Navigate to Hudder's configuration folder and create a new directory.
    The name of this directory will be the name of your hudpack.
  3. Go back to Hudder's settings and open the General section.
    Set the Main file setting to the name of the directory you just created.
  4. Inside the directory you created, create a file called pack.json.
The pack compiler accepts both folders and .zip files. As long as the pack is placed inside the Hudder folder, it can be loaded the same way. This file contains the metadata and configuration for the hudpack itself.



The pack.json file

Hudpack format version 1 was released in 10.0.0, version 2 in 10.1.0 and version 3 in 10.2.0 The pack.json file is the file that tells Hudder how your hudpack should behave. It defines things like pack settings, textures and which JavaScript files should be executed.

Here is a basic example: { "format_version": 3, "textures": [ "textures/example.png" ], "settings": { "example_setting": { "name": "Example setting", "type": "boolean", "default_value": true } }, "points": [ { "type": "topleft", "path": "main.js", "entry_function": "main" } ] }

The following properties are currently supported:
Property Required Description
format_version Yes The format version this hudpack requires/supports.
textures No A list of texture paths inside the hudpack. This is used if your hudpack wants to render textures that are bundled with it.
settings No A map of user-configurable settings exposed by the hudpack.
points Yes A list of execution points. These tell Hudder which script to run, when to run it and which function to call.


textures

The textures property is an array of paths to texture files inside the hudpack.

Example: "textures": [ "textures/example.png", "textures/icons/thing.png" ]

You only need to define this if your hudpack wants to render its own textures.

settings

The settings property lets you define settings that will appear in the hudpack's settings menu. Each entry inside settings uses its key as the internal setting name.

Each setting supports the following properties:
Property Required Description
name Yes The name shown to the user in the settings menu.
type Yes The setting type. Supported values are boolean, string, number, integer (whole numbers, minimum format version 3), dropdown (minimum format version 2) and hex.
default_value Yes The default value of the setting. This must match the given type.
values No An array of strings for the dropdown settings type (format version 2 or higher)


Example: "settings": { "show_thing": { "name": "Show thing", "type": "boolean", "default_value": true }, "text_color": { "name": "Text color", "type": "hex", "default_value": "#ffffff" } }

Inside JavaScript files you can retrieve the value of a hudpack setting using the built-in function getHudSetting(key). Example: let showThing = getHudSetting("show_thing");

points

The points property is an array of execution points. Each point tells Hudder which JavaScript file should be loaded and which function inside that file should be called.

Each point supports the following properties:
Property Required Description
type Yes Determines where or how this point is used. Supported values are topleft, bottomleft, topright, bottomright, mute and elements.
path Yes The path to the JavaScript file inside the hudpack.
entry_function Yes The name of the function that should be called when this point is executed.
conditions No A list of conditions that must all pass before this point is executed.


Example: "points": [ { "type": "topleft", "path": "main.js", "entry_function": "renderTopLeft" }, { "type": "elements", "path": "elements.js", "entry_function": "buildElements", "conditions": [ "removegui" ] } ]

If multiple points reference the same JavaScript file, they will share the same runtime and execution context. This means variables and state created in one point will persist and be accessible in other points that use the same script. A condition can be a boolean variable that Hudder has. If any condition fails, that point will not be executed.



Extra functions



Hudpacks also have extra functions that are only available with hudpacks, they are:
Function Minimum version Description
readHudpackFile(String filename) 2 Reads the file of the given name (Only files provided by the hudpack)
readBinaryHudpackFile(String filename) 2 Reads the file of the given name to an array of bytes (Only files provided by the hudpack)
